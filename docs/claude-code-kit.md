# Claude Code 導入キット 第三版（Claude Opus 5 対応）

活用ガイド（A4×2枚）の中身を、Claude Code のしくみに分解して配置したものです。
**ガイド本文（PDF/HTML）は人間用なので、Claude Code には読み込ませません。**

## 第二版からの変更点（重要）

Opus 5 は指示されなくても自分の作業を検証します。公式ガイドは、明示的な検証指示
（「最後に検証ステップを入れる」「サブエージェントで検証させる」「再確認する」）を
削除するよう求めています。残すと過剰な検証が走り、削っても品質は落ちません。

- CLAUDE.md から「betsujin-reviewer の検証を受けてから報告する」を削除
- app-dev-playbook から「第三段階｜自己検証」を削除（完成の定義は残す）
- betsujin-reviewer は自動起動をやめ、**あなたが明示的に呼ぶときだけ**動く設定に変更
- 代わりに CLAUDE.md へ **分量・作業範囲・委任の上限** を追加

第二版のキットを既に置いている場合は、上書きコピーしてください。

## 配置

このフォルダの中身を、プロジェクトの直下にそのままコピーします。

    あなたのプロジェクト/
    ├── CLAUDE.md            ← 常時ルール（毎セッション自動で読まれる。短く保つ）
    ├── LESSONS.md           ← 教訓ノート（資産四）
    └── .claude/
        ├── agents/
        │   └── betsujin-reviewer.md   ← 明示的に呼ぶときだけの独立レビュアー
        └── skills/
            ├── app-dev-playbook/      ← アプリ制作の既定仕様。分野ごとに増やす
            ├── nidan-review/          ← /nidan-review：二段レビュー
            ├── kyokun-note/           ← /kyokun-note：教訓ノート更新
            └── hikitsugi/             ← /hikitsugi：新セッション引き継ぎ

どのプロジェクトでも使いたいものは、~/.claude/skills/ と ~/.claude/agents/ へ。

## 使い方（一日の流れ）

1. 依頼はテンプレート（基本編・裏面）で一括して渡す。分量と範囲を必ず書く
2. 大きな作業だけプランモード（Shift+Tab）で計画を確認する
3. 実行は任せる。検証は指示しない（自分でやります）
4. 大事な成果物だけ、あなたの判断で「別の目で見て」と betsujin-reviewer を呼ぶ
5. セッションの締めに /kyokun-note で教訓を貯める
6. 会話が長くなったら /hikitsugi で仕切り直す

## 設定

- 思考は既定でオン。オフを探す必要はありません
- エフォートは high から。費用と速さを抑えたいときは low・medium を積極的に、
  難所だけ xhigh。旧モデルから引き継いだ設定は測り直してください
- コンテキストは既定かつ最大で100万トークン

## 育て方

- 手順書スキルは分野ごとに増やす（コラム執筆用、ラベル生成用など）。
  作り方：良い出力が出た直後に「いまの進め方を .claude/skills/◯◯/SKILL.md の
  形式で仕様書にして。確認や再チェックを促す手順は書かないで」と頼めば、
  Claude 自身に書かせられます
- description は「何ができるか」ではなく「いつ使うか」（発火条件）で書く
- モデルが更新されたら、公式のプロンプトガイドと移行ガイドを読ませて、
  不要になった指示と足すべき指示を洗い出させる
