# Claude Code 導入キット 第四版（Claude 5 世代）

活用ガイド（A4×2枚）の中身を、Claude Code のしくみに分解して配置したものです。
**ガイド本文（PDF/HTML）は人間用なので、Claude Code には読み込ませません。**

## 第三版からの変更点

Anthropic は Claude Code のシステムプロンプトの8割以上を削除し、コーディング評価に
測定可能な低下はありませんでした。過剰な制約が判断の邪魔をしていたためです。
その考え方をキットにも反映しました。

- **CLAUDE.md の中身を入れ替え**：汎用の振る舞いルール中心から、
  **リポジトリ固有の落とし穴**中心へ。冒頭のテンプレートを埋めてください
- **検証をスキルへ**：`.claude/agents/betsujin-reviewer.md` と `nidan-review` を廃止し、
  `.claude/skills/verify/`（SKILL.md ＋ rubric.md）に統合
- **段階的開示**：長いスキルを分割。app-dev-playbook は入口＋`design-notes.md` の形に
- **教訓ノートを任意化**：自動メモリが入ったため、LESSONS.md は
  「あなたの流儀」専用に縮小。まず外して様子を見てください

第三版を置いている場合は、上書きコピーしたうえで、
不要になった `.claude/agents/` と `.claude/skills/nidan-review/` を削除してください。

## 配置

    あなたのプロジェクト/
    ├── CLAUDE.md            ← 落とし穴が主役。短く保つ
    ├── LESSONS.md           ← 任意。あなたの流儀だけ
    └── .claude/skills/
        ├── verify/          ← 呼び出す検証スキル（SKILL.md ＋ rubric.md）
        ├── app-dev-playbook/← 固有の流儀（SKILL.md ＋ design-notes.md）
        ├── kyokun-note/     ← /kyokun-note：流儀を書き留める
        └── hikitsugi/       ← /hikitsugi：新セッション引き継ぎ

## 置いたあとに、まずやること

1. **CLAUDE.md の落とし穴を埋める。**思いつかなければ Claude に洗い出させます：

       このリポジトリで、初見の人がつまずきやすい点・一般的な慣習から
       外れている点を洗い出し、CLAUDE.md 用に箇条書きにしてください。
       ファイルを見れば分かることは書かないでください。

2. **`/doctor` を実行する。**スキルと CLAUDE.md を適正な大きさに整える
   コマンドです。提案は鵜呑みにせず、一つずつ判断してください。
3. **rubric.md を自分の基準に書き換える。**検証役に持たせる物差しです。

## 使い方

1. 依頼はテンプレート（基本編・裏面）で一括して渡す。分量と範囲を必ず書く
2. 大きな作業だけプランモード（Shift+Tab）で計画を確認する
3. 実行は任せる。検証は指示しない
4. 重要な成果物のときだけ「verify スキルで検証して」と明示的に呼ぶ
5. 会話が長くなったら /hikitsugi で仕切り直す

## 書き方の原則

- **禁止の列挙より、基準の一文。**「コメントを書くな」ではなく
  「周囲のコードと同じように読めるコードを書く」
- **実証できる失敗が無い禁止は書かない。**念のためのルールは判断の邪魔になります
- **当たり前は書かない。**ファイルやコードを見れば分かることは省く
- **例示より参照。**やり方の例は探索範囲を狭めます。実物（モックアップ・
  テストスイート・コード・ルーブリック）を渡すほうが効きます
- **一枚に詰めない。**長くなったら分割し、必要なときに読まれる形にする

## モデルが変わったら

`/doctor` を実行し、そのうえで公式の最新プロンプトガイドと移行ガイドを読ませて、
不要になった指示と足すべき指示を洗い出させてください。
削ったあとは、いつもの仕事を一度通して確かめること。
悪くなった点があれば、そこだけ基準の一文として戻します。
